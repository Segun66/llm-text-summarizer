# Архитектура LLM Text Summarizer

## Ответственность слоёв

| Слой | Модуль | Ответственность |
| --- | --- | --- |
| Composition root | `main.py` | Фабрика приложения, lifespan, подключение LLM-фабрики и HTTP-отображение ошибок |
| API | `app/api/routes.py` | POST /summarize, GET /health, Depends, HTTP-статус по результату сервиса |
| Models | `app/models/summarize.py` | Pydantic v2: вход, выход и схемы ошибок для OpenAPI |
| Services | `app/services/summarizer.py` | Сценарий сокращения: LLM → постобработка; fallback при недоступности |
| Cache | `app/services/cache.py` | Protocol SummaryCache (get/set) и ограниченный потокобезопасный TTL/LRU-кеш процесса |
| LLM contract | `app/llm/base.py` | Protocol LLMClient: async generate(messages) → str |
| LLM lifecycle | `app/llm/factory.py` | Проверяемый TLS, создание и гарантированное закрытие пула HTTP-соединений |
| LLM prompts | `app/llm/prompts.py` | System-правила с max_length и отдельное user-сообщение |
| LLM adapter | `app/llm/gigachat.py` | OAuth, кеш токена, REST, повторы, валидация ответов и преобразование ошибок |
| Config | `app/config/settings.py` | pydantic-settings, окружение и .env, ограничения параметров, SecretStr |
| Utils | `app/utils/postprocessing.py` | Нормализация пробелов и переводов строк, проверка непустого результата |
| Errors | `app/utils/errors.py` | Общие исключения без зависимости от FastAPI и httpx |
| Tests | `tests/` | Изолированные тесты клиента, сервиса, конфигурации и API, интеграция с MockTransport |

Сервис зависит от Protocol, поэтому другой LLM-адаптер подключается в composition
root без изменения маршрута и бизнес-сценария. Клиент не знает про HTTP-статусы
нашего API. API не формирует промпт и не управляет токенами.

## Поток данных

~~~mermaid
flowchart TD
    A["Валидированная SummarizeRequest"] --> B["SHA-256 ключ: model + prompt version + normalized text + max_length"]
    B --> C["SummaryCache.get"]
    C -->|попадание| D["success, cached=true"]
    C -->|промах| E["llm/prompts.py: system + user"]
    E --> F["LLMClient.generate"]
    F -->|текст| G["Постобработка: пробелы, пустые строки, длина, непустота"]
    G --> H["SummaryCache.set"]
    H --> I["success, cached=false"]
    F -->|недоступность или таймаут| J["Начало исходного текста: fallback, cached=false"]
    F -->|ошибка ответа или запроса| K["Исключение без кеширования"]
    G -->|пустой результат| K
~~~


1. При старте Settings проверяет обязательный ключ, оба HTTPS URL, диапазоны
   числовых параметров и файл CA. Импорт `main` не требует ключа: конфигурация
   загружается в lifespan. Некорректная конфигурация останавливает запуск.
2. Один `httpx.AsyncClient` живёт весь lifespan, переиспользует соединения
   и закрывается при остановке. Каждый worker имеет свой клиент и кеш токена.
3. Pydantic удаляет крайние пробелы входа, запрещает пустую строку, лишние поля
   и длину больше 10 000 символов. max_length — строгое целое 50–1000,
   по умолчанию 300. При ошибке сервис не вызывается.
4. SummarizationService получает валидированную SummarizeRequest, проверяет
   SummaryCache и на промахе формирует сообщения через llm/prompts.py.
   Правила находятся в system-сообщении, исходный текст — в user-сообщении.
   LLMClient.generate(messages) выполняется только на промахе кеша.
5. OAuth-токен кешируется в памяти процесса. `expires_at` интерпретируется
   как Unix timestamp в миллисекундах; обновление начинается за 30 секунд
   до истечения. `asyncio.Lock` сериализует получение токена при конкуренции.
6. Ответы 401/403 немедленно дают LLMAuthenticationError без повторов,
   обновления токена и fallback. Токен обновляется по сроку действия.
7. Клиент проверяет структуру JSON и принимает только `finish_reason=stop`.
   Обрезанная генерация (`length`) и блокировка (`blacklist`) не выдаются за успех.
8. Постобработка нормализует горизонтальные пробелы и CRLF, сохраняет переносы
   непустых строк и содержимое; пустые строки удаляются.
   Пустой после нормализации результат считается ошибкой.
   Она ограничивает длину результата max_length символами с учётом многоточия.
   Она не пытается исправлять факты, Markdown или смысл ответа.
9. При LLMUnavailableError (включая timeout/network/rate-limit) после
   исчерпания допустимых попыток сервис формирует fallback из
   нормализованного начала исходного текста с тем же ограничением длины.
   Он возвращает DTO с summary, status и cached. Маршрут отображает fallback
   в HTTP 503, success — в HTTP 200. Сервис не зависит от FastAPI и HTTP-кодов.
   Только успешно обработанный результат сохраняется в SummaryCache.
   При попадании в кеш возвращается success/cached=true без промпта и LLM.
   Fallback (начало исходного текста, не результат генерации) и ошибки не кешируются.
10. GET /health возвращает 200 {status: "ok"} без Depends и вызовов LLM.
    Проверка процесса не отражает доступность провайдера; конфигурация приложения
    по-прежнему должна быть корректной для завершения старта.

## Точки обработки ошибок

| Точка | Поведение | HTTP-результат |
| --- | --- | --- |
| Settings / TLS setup | Ошибка конфигурации; приложение не начинает принимать запросы | Ошибка старта |
| Валидация входа | Стандартная RequestValidationError FastAPI | 422, detail: список ошибок |
| Генерация: 400, 413, 422 | LLMRequestError, без повторов | 422, detail: строка |
| Ошибка авторизации OAuth/генерации (401/403; также OAuth 400) | LLMAuthenticationError, без повторов и fallback | 502, detail: строка |
| Прочая постоянная ошибка HTTP | LLMServiceError, без повторов и fallback | 502, detail: строка |
| 429, 5xx | Максимум 3 попытки; затем LLMUnavailableError → fallback | 503, summary/status/cached |
| Ошибка соединения / транспортная ошибка | Максимум 3 попытки; затем LLMUnavailableError → fallback | 503, summary/status/cached |
| Таймаут httpx | Максимум 3 попытки; затем LLMTimeoutError → fallback | 503, summary/status/cached |
| Не-JSON, неверная структура, непригодный OAuth-токен | LLMInvalidResponseError, без повторов | 502 |
| Незавершённая или заблокированная генерация | LLMInvalidResponseError, без повторов | 502 |
| Пустое краткое содержание | LLMInvalidResponseError в постобработке | 502 |
| Неожиданная ошибка программирования | Стандартный обработчик FastAPI/Starlette | 500 |

Повторы применяются отдельно к OAuth и генерации. Используются
`stop_after_attempt` (максимум 3) и `wait_random_exponential` (full jitter);
параметры
задержки поступают из Settings. Retry-After отдельно не обрабатывается.
Предел timeout относится к сетевым фазам отдельной попытки; общий deadline всего
сценария отсутствует. Отмена async-задачи не перехватывается.

Fallback возвращает начало исходного текста, а ошибки — фиксированные сообщения.
Исходный ответ провайдера,
ключ и bearer-токен в ответ не включаются. Ключ хранится в SecretStr, исходный
текст и ответы приложение не логирует и не записывает на диск. Успешные
summary хранятся в ограниченном TTL-кеше памяти процесса; исходный текст
передаётся провайдеру и обрабатывается в пределах запроса. На уровне прокси следует
отдельно настраивать политику логирования и ограничения HTTP-тела при публикации.

## Проверки и границы проекта

Тесты используют asyncio.run, pytest и встроенные транспорты httpx: дополнительные
async-плагины и библиотеки моков не нужны. API-зависимость подменяется через
`dependency_overrides`; интеграционный тест проходит весь сценарий от JSON
до постобработки с подменённым внешним транспортом и lifespan приложения.

В проекте нет БД, очереди, ORM, SDK GigaChat, автоматического chunking и хранения
истории. Настоящий вызов GigaChat требует ключа и доверенной цепочки сертификатов.
Краткость, качество и соблюдение промпта зависят от выбранной модели.

Подтверждённый протокол, типы ошибок и ручная проверка: [GIGACHAT.md](GIGACHAT.md).

Кеш в памяти по умолчанию ограничен 128 записями, использует LRU и TTL 300 секунд.
Параметры GIGACHAT_CACHE_MAX_ENTRIES и GIGACHAT_CACHE_TTL_SECONDS читаются из Settings.
Срок действия проверяется monotonic clock: get не продлевает TTL, set обновляет его.
Просроченная запись — cache expired, для вызывающего сервиса это cache miss (None).
Записи очищаются при get/set; фоновая задача не требуется.
threading.Lock защищает короткие операции без await и I/O, включая доступ из разных
потоков. Отдельный экземпляр создаётся для каждого worker, без общего хранилища.
Ключ содержит имя модели, версию промпта, нормализованный текст
и max_length; в ключе хранится только SHA-256, секреты не участвуют в вычислении.
Нормализация сводит все пробельные последовательности к одному пробелу, сохраняя
регистр и пунктуацию; тот же текст передаётся в prompts.py. При смене промпта нужно
обновить PROMPT_VERSION. Параллельные промахи не объединяются в один LLM-вызов.
Ошибки реализации кеша распространяются вызывающему коду, а не маскируются под
недоступность LLM. Интерфейс кеша допускает замену на внешнее хранилище.
